Refresh Opportunity Scoring for Search Content

A FlyRank Search Intelligence capstone by Taha Shan

Abstract

This project asks which existing content items should be reviewed first for refresh or CTR improvement. I framed the problem as a ranking task for a content or SEO review queue. Using the FlyRank ML Internship warehouse dataset, I built March 2026 features and used April 2026 impression decline as a proxy outcome. A logistic regression model outperformed the hand-written baseline on the same client-grouped test split, improving Precision@50 from 0.10 to 0.30. The result is a public-safe ranked recommendation workflow for deciding which content items deserve human review first.

Introduction / Problem Statement

Content teams have limited time and cannot manually inspect every page every month. The decision this work supports is: which content items should be reviewed first? The recommended action is not automatic publishing. The action is to inspect the content item, check search intent and performance signals, then decide whether to refresh, improve title or snippet, merge, prune, protect, or monitor.

Data

This project uses the FlyRank ML Internship warehouse dataset. I used the daily content performance fact table and the content dimension table. March 2026 is the feature window, and April 2026 is the outcome window for the proxy label.

Methodology

I framed the lane as a ranking/scoring task. The proxy target is whether a content item loses at least 20% of March impressions in April. The features are known at the March decision moment: word count, search volume, competition, days since last content touch, March impressions, March clicks, March CTR, March average position, March sessions, March engagement rate, and March pageviews.

The baseline is a hand-written score based on visibility, low CTR, weaker position, and staleness. The learned models were logistic regression, decision tree, and random forest. All models were compared on the same client-grouped split so content from the same client did not cross between train and test. The main metric is Precision@50 because a review queue is only useful if the top recommendations are strong.

The best model was logistic regression. On the same client-grouped test split, it found three times as many proxy-positive review candidates in the top 50 as the baseline rule.

Limitations & Honest Framing

This work is decision support, not proof of causality. It does not prove that refreshing a page will cause rankings or traffic to improve.

The proxy label uses a future drop in impressions, but it does not prove why the drop happened. Search performance can change because of seasonality, SERP features, competitor changes, tracking coverage, content intent, or Google changes outside this dataset. The recommendations should be treated as a review queue for humans, not an automatic action system.

Ranked Recommendations

The ranked output gives each content item a model score, an action label, and a reason code. For MODEL_HIGH_RISK_LOW_CTR, the review should focus on title, snippet, search intent match, and SERP layout. For MODEL_HIGH_RISK_REFRESH, the review should focus on freshness, completeness, ranking position, engagement, and business value.

The action playbook is: inspect the top-ranked items, verify that the search intent is worth serving, decide whether the right action is refresh, CTR improvement, merge, prune, protect, or monitor, and avoid making changes automatically from the score alone.
